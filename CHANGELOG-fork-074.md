| 3 | [`82e15f2f`](../../commit/82e15f2f) + [`4b33e58d`](../../commit/4b33e58d) | fix | orchestrator / webhook | Ported from `fork-073` row 4. Reusing the existing payload shape (instead of a parallel `{status:"no_reply",...}` schema) means the receiver doesn't need any contract changes — the reason text alone carries enough signal to distinguish a deliberate non-response from a dropped request. |
| 4 | [`dc2e1b1c`](../../commit/dc2e1b1c) | feat | channels / config | Ported from `fork-073` row 5. Added `[agent.precheck]` config section (`ChannelPrecheckConfig`) with three knobs: `enabled` (kill-switch, default `true`), `model: Option<String>` (default `None` → falls back to the route model), and `timeout_secs` (hard ceiling, default `5`). The channel orchestrator's reply-intent classifier now reads these — it wraps `classify_channel_reply_intent` in `tokio::time::timeout`, fails open to `REPLY` on both error and timeout, and emits a structured `elapsed_ms` / `model` log on completion (replacing the previous unconditional `precheck_ms` log). When `enabled = false` the precheck is skipped entirely and every channel message goes straight to the full agent loop. Conflict on v0.7.4 base: upstream still had the simple un-timed `classify_channel_reply_intent` call here — replaced wholesale with the wrapped/configurable version. Recreated from upstream `zeroclaw-labs/zeroclaw#6068`. | Mirrors the existing `ContextCompressionConfig.summary_model` pattern so operators can route the lightweight REPLY/NO_REPLY classifier to a faster/cheaper model than the main reasoning model. The timeout was prompted by a field incident where a Venice precheck silently took 57s — long-tail latency on the classifier was disguised as a gap before `"Starting LLM call"` and held up every channel turn. The hard ceiling caps that worst case (defaulting to fail-open preserves the prior "always reply if unsure" semantics), and the new structured log makes precheck cost legible going forward. The `model` field must be a literal model name on the same provider as the route — channel-orchestrator providers are built via `create_resilient_provider_nonblocking` without `RouterProvider`, so `hint:<name>` routing hints are not resolved here. |
